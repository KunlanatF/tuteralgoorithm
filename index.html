1) Sorting by Counting — Comparison Counting และ Distribution Counting
อ้างอิงสไลด์: Week 7 • 7.1 Sorting by Counting (Comparison counting sort) และ Distribution counting

ก) ComparisonCountingSort(A[0..n−1])

เปรียบเทียบสมาชิกเป็นคู่ ๆ แล้วใช้จำนวนค่าที่น้อยกว่าเป็นตำแหน่งในอาร์เรย์ผลลัพธ์

เริ่ม Count[i] = 0
ถ้า A[i] < A[j] ให้ Count[j] ← Count[j]+1
มิฉะนั้น Count[i] ← Count[i]+1
จากนั้น S[Count[i]] ← A[i]

ตัวแปรตามสไลด์: A[0..n−1] = ข้อมูลเดิม, Count[0..n−1] = จำนวนสมาชิกที่น้อยกว่าเพื่อหาตำแหน่ง, S[0..n−1] = ผลลัพธ์ที่เรียงแล้ว

Time: จำนวนการเปรียบเทียบเท่ากับ n(n−1)/2 จึงเป็น O(n²) • Space: O(n)

ข) DistributionCountingSort(A[0..n−1], l, u)

ใช้เมื่อข้อมูลเป็นจำนวนเต็มอยู่ในช่วงจำกัด l ถึง u โดยนับความถี่ แล้วสะสมจำนวนเพื่อหาตำแหน่งของแต่ละค่า

D[0..u−l] ← 0
D[A[i]−l] ← D[A[i]−l] + 1
สะสม D[j] ← D[j−1] + D[j]
S[D[A[i]−l]−1] ← A[i]; D[A[i]−l] ← D[A[i]−l]−1 (ไล่ A จากขวาไปซ้าย)

ตัวแปรตามสไลด์: l = ค่าต่ำสุด, u = ค่าสูงสุด, D = frequency/distribution array, S = sorted array และ k = u−l+1 คือจำนวนค่าที่เป็นไปได้

Time: O(n+k) • Space: O(n+k)

ข้อสอบชอบสับสน: Comparison counting sort เป็น O(n²) เพราะเปรียบเทียบเป็นคู่ ส่วน Distribution counting เป็น O(n+k) เพราะวนตามจำนวนข้อมูลและช่วงค่า อย่าจำว่า “Counting Sort ทุกแบบเป็น O(n+k)”
2) String Matching — Horspool และ Boyer–Moore
อ้างอิงสไลด์: Week 7 • 7.2 Input Enhancement in String Matching (ตัวอย่าง Text s₀ ถึง sₙ₋₁ และ Pattern = BARBER)

ให้ Text เป็น s₀, …, sₙ₋₁ และ Pattern ยาว m ตัวอักษร เป้าหมายคือขยับ Pattern ข้าม Text โดยไม่เริ่มเทียบใหม่ทีละช่องทุกครั้ง

Horspool’s algorithm

  1. เริ่มค่า shift ของทุกอักขระเป็น m
  2. พิจารณา Pattern จากตำแหน่ง 0 ถึง m−2 (ไม่ใช้ตัวสุดท้ายสร้างตาราง)
  3. ถ้ามีอักขระซ้ำ ให้ตำแหน่งที่อยู่ขวาสุดในช่วงนี้เป็นตัวกำหนด shift
  4. เทียบ Pattern จากขวาไปซ้าย หากไม่ตรง ให้ดูอักขระใน Text ที่อยู่ใต้ปลายขวาของ Pattern แล้วเลื่อนตามตาราง
shift(P[j]) = m−1−j, เมื่อ 0 ≤ j ≤ m−2
ถ้าอักขระไม่อยู่ใน P[0..m−2] → shift = m

ตัวอย่างตามสไลด์: Pattern = BARBER, m=6 → shift(B)=2, shift(A)=4, shift(R)=3, shift(E)=1, อักขระอื่น=6

Boyer–Moore

เปรียบเทียบจากขวาไปซ้ายเหมือนกัน โดยสไลด์กล่าวถึงการเลื่อน 2 แบบ:

  • Bad-symbol shift: ใช้ตัวอักษรที่ไม่ตรงกัน c และจำนวนตัวอักษรที่ตรงกัน k ตามนิยามในสไลด์
  • Good-suffix shift: ใช้เมื่อ suffix ด้านท้ายตรงกันแล้วจึงเกิด mismatch

ในการเลื่อน ใช้ค่าที่ปลอดภัยตามกฎของ Boyer–Moore เพื่อไม่ข้ามตำแหน่งที่อาจจับคู่ได้

จำความต่าง: Horspool ใช้อักขระใต้ปลายขวาของ Pattern เพื่อเปิด shift table; Boyer–Moore พิจารณา bad-symbol และ good-suffix shift

Time Complexity (สรุปการวิเคราะห์เสริม): Worst case ของเวอร์ชันพื้นฐานมักเขียน O(nm); เฉลี่ยหลายกรณีสามารถข้ามตำแหน่งได้มาก แต่ไม่ควรตอบว่า worst case เป็น O(n) โดยไม่มีเงื่อนไข

3) Hash Table — Collision
อ้างอิงสไลด์: Week 7 • 7.3 Hashing — Open Hashing (Separate Chaining) และ Closed Hashing (Open Addressing)

Hash function แปลง key เป็นตำแหน่งจัดเก็บในตาราง เช่น h(k)=k mod M (ตัวอย่าง h(k)=k mod 7 ใช้ฝึกคำนวณได้)

Collision เกิดเมื่อ key ต่างกันถูกส่งไป index เดียวกัน

วิธีหลักการจุดที่ควรรู้
Separate Chainingแต่ละช่องเก็บ list/bucket ของ key ที่ชนกันโหลดเกินจำนวนช่องได้ แต่ list ยาวขึ้น
Linear Probingลองช่องถัดไปทีละ 1: (h(k)+i) mod mเกิด primary clustering ได้
Quadratic Probingเลื่อนด้วยกำลังสอง เช่น h(k)+i²ลด clustering บางแบบ แต่อาจไม่เจอช่องว่างทุกช่อง
Double Hashingใช้ hash ตัวที่สองกำหนดระยะเลื่อนกระจายการ probe ได้ดีขึ้น

ตัวอย่าง: h(k)=k mod 7, ใส่ 10, 17, 24 → ทั้งหมดชนที่ช่อง 3 เพราะเหลือเศษ 3

Load factor α = จำนวน key ที่เก็บ / จำนวนช่องในตาราง

Time Complexity (วิเคราะห์เสริม): ค้นหา/เพิ่มโดยเฉลี่ย O(1) เมื่อ hash กระจายดีและ load factor เหมาะสม; worst case O(n) หากหลาย key ชนกัน

ในสไลด์ Week 7 เน้นการจำแนกวิธีแก้ collision เป็น Open Hashing และ Closed Hashing; ตัวเลข complexity ในหน้านี้เป็นสรุปการวิเคราะห์ทั่วไป

4) B-Tree — คุณสมบัติและการแทรก
อ้างอิงสไลด์: Week 7 • 7.4 B-Trees (มีตัวอย่าง B-tree of order 4)

B-Tree เป็น balanced multiway search tree; node หนึ่งเก็บหลาย key ได้ และใบทั้งหมดอยู่ระดับเดียวกัน

  • key ในแต่ละ node เรียงจากน้อยไปมาก
  • node ที่มีลูก k คน จะมี key k−1 ตัว
  • ทุก leaf อยู่ depth เดียวกัน จึงรักษาความสูงสมดุล
  • สำหรับ B-Tree ขั้นต่ำ t (minimum degree): node ที่ไม่ใช่ root มี key อย่างน้อย t−1 และไม่เกิน 2t−1; มีลูกไม่เกิน 2t

วิธีแทรก: ค้นหา leaf ที่ถูกตำแหน่ง → เพิ่ม key ให้เรียง → ถ้า node เต็มให้ split โดยเลื่อน median ขึ้น parent → ถ้า parent เต็มให้ split ต่อขึ้นไป → ถ้า root split จะได้ root ใหม่และความสูงเพิ่ม 1

Time Complexity (วิเคราะห์เสริม): ค้นหา/แทรกมีจำนวนระดับประมาณ O(logm n) เมื่อ m คือ order/จำนวนลูกสูงสุดและ n คือจำนวน key; หากถือว่า order คงที่ มักย่อเป็น O(log n)

จำภาพ: “เต็ม → ผ่าครึ่ง → ดันค่ากลางขึ้น”
คำว่า order ของ B-Tree ใช้ต่างนิยามตามตำราได้ ตรวจว่าคลาสกำหนด order = จำนวนลูกสูงสุด หรือใช้ minimum degree t ก่อนคำนวณจำนวน key
5) Dynamic Programming — คิดอย่างไร
อ้างอิงสไลด์: Week 8 • Dynamic Programming, recurrence ของ Fibonacci และตัวอย่างพื้นฐาน

ใช้เมื่อมีคุณสมบัติหลัก 2 อย่าง

  • Overlapping subproblems: โจทย์ย่อยเดิมถูกคำนวณซ้ำ เช่น Fibonacci
  • Optimal substructure: คำตอบที่ดีที่สุดของปัญหาใหญ่สร้างจากคำตอบที่ดีที่สุดของปัญหาย่อยที่เกี่ยวข้อง

ขั้นตอนออกแบบ DP: 1. นิยาม state ให้ชัด 2. เขียน recurrence 3. กำหนด base case 4. กำหนดลำดับเติมตาราง 5. อ่านคำตอบจาก cell ที่ถูกต้อง

แบบทำงานยังไง
Top-down / Memoizationเรียก recursion แล้วจำผลโจทย์ย่อยที่เคยคำนวณ
Bottom-up / Tabulationเริ่ม base case แล้วเติมตารางจากโจทย์เล็กไปใหญ่
ก่อนเติมตัวเลขให้เขียนก่อนว่า dp[i] หมายถึงอะไร ถ้า state ไม่ชัด ตารางจะผิดได้ง่าย
6) Change-marking / Coin Change — จำนวนเหรียญน้อยที่สุด
อ้างอิงสไลด์: Week 8 • 8.1 Three Basic Examples, Change-marking problem (สไลด์ใช้ F(n), dⱼ และ F(0)=0)

ให้ F(n) เป็นจำนวนเหรียญน้อยที่สุดที่ใช้แลกเงินจำนวน n และให้ dⱼ เป็นมูลค่าเหรียญชนิดที่ j โดยใช้เหรียญแต่ละชนิดได้ไม่จำกัด

F(n) = min { F(n−dⱼ) : n ≥ dⱼ } + 1, เมื่อ n > 0
F(0) = 0

อ่านสูตร: ลองใช้เหรียญ dⱼ ที่ไม่เกินยอด n แล้วเอาจำนวนเหรียญที่ดีที่สุดของยอดที่เหลือมา +1 จากนั้นเลือกค่าต่ำสุด

ตัวอย่างสไลด์: ยอด 20 ใช้เหรียญ {1,2,5,10}; อีกตัวอย่างคือยอด 6 กับเหรียญ {1,3,4} ได้คำตอบ 2 เหรียญ คือ 3+3

Time Complexity: O(A·m) เมื่อ A คือยอดเงินเป้าหมาย และ m คือจำนวนชนิดเหรียญ • Space: O(A)

สไลด์ใช้ F(n) ไม่ใช่ dp[x] — ในห้องทดลองอาจแสดง dp[x] เพื่อให้อ่านง่าย แต่เวลาซ้อมตอบอัตนัยให้ใช้นิยาม F(n) และระบุความหมายก่อนเติมตาราง

8) The Knapsack Problem — 0/1 Knapsack
อ้างอิงสไลด์: Week 8 • 8.2 The Knapsack Problem and Memory Functions (นิยาม F(i,j), wᵢ, vᵢ และ W)

มีสิ่งของ n ชิ้น โดยชิ้นที่ i มีน้ำหนัก wᵢ และมูลค่า vᵢ; ความจุกระเป๋าเท่ากับ W. ให้ F(i,j) เป็นมูลค่าสูงสุดจากสิ่งของ i ชิ้นแรก เมื่อความจุที่ใช้ได้คือ j

ถ้า wᵢ > j: F(i,j) = F(i−1,j)
ถ้า wᵢ ≤ j: F(i,j) = max{F(i−1,j), vᵢ + F(i−1,j−wᵢ)}
Base cases: F(0,j)=0 และ F(i,0)=0

ทางเลือกมี 2 ทาง: ไม่เอาชิ้นที่ i ได้ F(i−1,j); เอาชิ้นที่ i ได้ vᵢ + F(i−1,j−wᵢ). ใช้แถว i−1 ในทั้งสองทาง เพื่อให้แต่ละชิ้นถูกใช้ได้ไม่เกิน 1 ครั้ง

ตัวอย่าง: A=(w₁=2,v₁=3), B=(w₂=3,v₂=4), C=(w₃=4,v₃=5), W=5 → เลือก A+B มูลค่า 7

Time: O(nW) • Space: O(nW) สำหรับตาราง 2 มิติ

ให้จำสัญลักษณ์ตามสไลด์: F(i,j), wᵢ, vᵢ, W (ไม่ใช่ใช้ w ตัวเดียวแทนทั้งน้ำหนักสิ่งของและความจุ)

Fractional Knapsack เป็นอีกปัญหาหนึ่ง: แบ่งสิ่งของได้และใช้ Greedy; 0/1 Knapsack แบ่งไม่ได้และใช้ DP ในบทนี้

9) Warshall’s Algorithm — Transitive Closure
อ้างอิงสไลด์: Week 8 • 8.4 Warshall’s and Floyd’s Algorithms (สไลด์แสดงเมทริกซ์ R⁽⁰⁾)

หา Transitive Closure: ตรวจว่า vertex i สามารถเดินทางไปถึง vertex j ได้หรือไม่ ค่าของเมทริกซ์เป็น 1/0 ไม่ใช่ระยะทาง

R⁽ᵏ⁾[i,j] = R⁽ᵏ⁻¹⁾[i,j] OR (R⁽ᵏ⁻¹⁾[i,k] AND R⁽ᵏ⁻¹⁾[k,j])

เริ่มจาก R⁽⁰⁾ เป็น adjacency matrix: มี edge จาก i ไป j ให้ใส่ 1; ไม่มีให้ใส่ 0. ในรอบ k อนุญาตให้ใช้ vertex k เป็นจุดกลางเพิ่มขึ้น

Time: O(V³) เพราะมีลูปตาม k, i, j • Space: O(V²)

จำตามสไลด์: ถ้า i ไปถึง k ได้ และ k ไปถึง j ได้ ก็ทำให้ i ไปถึง j ได้ (OR/AND)
10) Floyd’s Algorithm — All-Pairs Shortest Paths
อ้างอิงสไลด์: Week 8 • 8.4 Floyd’s Algorithm for the All-Pairs Shortest-Paths Problem

หาเส้นทางสั้นที่สุดของ ทุกคู่ ของ vertex โดยค่อย ๆ อนุญาตให้ vertex k เป็นจุดกลางได้

d⁽ᵏ⁾ᵢⱼ = min{d⁽ᵏ⁻¹⁾ᵢⱼ, d⁽ᵏ⁻¹⁾ᵢₖ + d⁽ᵏ⁻¹⁾ₖⱼ}, k ≥ 1
d⁽⁰⁾ᵢⱼ = wᵢⱼ

ตามสไลด์ d⁽ᵏ⁻¹⁾ᵢⱼ คือระยะทางที่รู้ก่อนอนุญาตจุดกลาง k; เปรียบเทียบระหว่างไม่ผ่าน k กับผ่าน k แล้วเลือกค่าน้อยกว่า

เริ่มจาก W=[wᵢⱼ] เป็นเมทริกซ์น้ำหนักเริ่มต้น (ไม่มี edge แทน ∞; ระยะจากจุดไปตัวเองมักเริ่ม 0)

Time: O(V³) • Space: O(V²)

Warshall: R เป็น Boolean ใช้ OR/AND ตอบ “ไปถึงไหม”; Floyd: d เป็นตัวเลข ใช้ min/+ ตอบ “ระยะทางสั้นที่สุดเท่าไร”
11) Greedy — Local vs Global Optimum
อ้างอิงสไลด์: Week 9 • Greedy Technique — แนวคิดเลือก local optimum เพื่อมุ่งไปยัง optimal solution

Greedy เลือกตัวเลือกที่ดีที่สุดตามเกณฑ์เฉพาะหน้า (local choice) โดยไม่ย้อนกลับ แล้วหวังว่าจะได้คำตอบดีที่สุดทั้งปัญหา (global optimum)

ข้อดีคือง่ายและเร็ว แต่ ไม่ได้รับประกันว่า optimal ทุกโจทย์ ต้องพิสูจน์ว่าการเลือกเฉพาะหน้าปลอดภัย หรือรู้ว่าโจทย์นั้นมี greedy-choice property และ optimal substructure

การสอบถามข้อจำกัด ให้ตอบว่า “การเลือกที่ดูดีที่สุดตอนนี้ ไม่จำเป็นต้องนำไปสู่คำตอบดีที่สุดโดยรวมเสมอ”
12) Prim vs Kruskal — Minimum Spanning Tree
อ้างอิงสไลด์: Week 9 • 9.1 Prim’s Algorithm และ 9.2 Kruskal’s Algorithm

MST เชื่อม vertex ทุกตัวในกราฟไม่กำกับที่เชื่อมถึงกัน ด้วยน้ำหนักรวมต่ำที่สุด และมี V−1 edges

PrimKruskal
วิธีคิดเริ่มจาก vertex หนึ่ง แล้วขยาย treeเรียง edges ทั้งหมดจากน้อยไปมาก
เลือก edgeถูกที่สุดที่เชื่อมจาก tree ออกไป vertex นอก treeถูกที่สุดที่ไม่ทำให้เกิด cycle
ป้องกัน cycleเลือกข้าม cut ไปยัง vertex ใหม่ตรวจด้วย Union-Find / Disjoint Set
Time ทั่วไปO(E log V) ด้วย heapO(E log E) จากการ sort edges

จำง่าย: Prim = โตจากต้นไม้หนึ่งต้น; Kruskal = เก็บ edge ถูกสุดทั่วกราฟทีละเส้น

อย่าสับสน MST กับ Shortest Path: MST ลดผลรวมน้ำหนักของโครงข่าย แต่ไม่ได้ทำให้ระยะทางจากแหล่งเริ่มไปทุกจุดสั้นที่สุด
13) Dijkstra — Shortest Path จากแหล่งเริ่มต้น
อ้างอิงสไลด์: Week 9 • 9.3 Dijkstra’s Algorithm

หาค่าระยะทางสั้นที่สุดจาก source หนึ่งจุดไปยังจุดอื่นในกราฟที่มีน้ำหนัก ไม่ติดลบ

  1. กำหนด dist[source]=0 จุดอื่นเป็น ∞
  2. เลือก vertex ที่ยังไม่ยืนยันและมี dist ต่ำที่สุด
  3. พิจารณาเพื่อนบ้าน v: ถ้า dist[u]+w(u,v) < dist[v] ให้อัปเดต dist[v]
  4. ทำซ้ำจนไม่มี vertex ให้เลือกหรือทุกจุดที่ต้องการได้รับการยืนยัน
relax(u,v): dist[v] = min(dist[v], dist[u] + weight(u,v))

Time: O((V+E) log V) ด้วย priority queue/binary heap; O(V²) ด้วยเมทริกซ์/การหา minimum แบบง่าย

ห้ามใช้ Dijkstra กับ edge ที่มีน้ำหนักติดลบโดยทั่วไป เพราะการยืนยันระยะทางต่ำสุดอาจผิด ใช้ Bellman–Ford ในกรณีที่ต้องรองรับน้ำหนักติดลบแทน
14) Activity Selection
อ้างอิงเสริมตามรายการหัวข้อสอบ: Activity Selection ไม่ได้แสดงรายละเอียดใน PDF Week 9 ที่แนบมา

เลือกจำนวนกิจกรรมที่ไม่ทับช่วงเวลากันให้ได้มากที่สุด

Greedy rule: เรียงตามเวลาเสร็จจากน้อยไปมาก เลือกกิจกรรมแรก แล้วเลือกกิจกรรมถัดไปที่เวลาเริ่ม ≥ เวลาเสร็จของกิจกรรมล่าสุด

ตัวอย่าง: A=(1,3), B=(2,5), C=(4,6), D=(6,7) → เลือก A, C, D ได้ 3 กิจกรรม

หลัง sort แล้ว scan หนึ่งรอบ: O(n); รวม sort มักเป็น O(n log n)

เกณฑ์คือ จบเร็วที่สุด ไม่ใช่เริ่มเร็วที่สุด หรือมีระยะเวลาสั้นที่สุด
15) Fractional Knapsack
อ้างอิงเสริมตามรายการหัวข้อสอบ: Fractional Knapsack ไม่ได้แสดงรายละเอียดใน PDF Week 9 ที่แนบมา

สิ่งของแบ่งเอาบางส่วนได้ เลือกตามอัตราส่วนมูลค่าต่อน้ำหนัก vᵢ/wᵢ จากมากไปน้อย

  1. คำนวณ vᵢ/wᵢ ของทุกชิ้น
  2. เรียง ratio จากมากไปน้อย
  3. หยิบทั้งชิ้นจนใส่ไม่ได้ แล้วหยิบเศษส่วนของชิ้นถัดไปให้เต็มความจุ

Time O(n log n) เพราะการเรียง

การหยิบตาม ratio รับประกัน optimal สำหรับ Fractional Knapsack แต่ไม่รับประกันสำหรับ 0/1 Knapsack
16) Huffman Coding
อ้างอิงสไลด์: Week 9 • 9.4 Huffman Trees and Codes

สร้างรหัสที่มีความยาวแปรผันตามความถี่ของสัญลักษณ์ เพื่อลดความยาวรหัสเฉลี่ย; ตัวที่พบบ่อยควรได้รหัสสั้นกว่า

  1. ใส่สัญลักษณ์ทั้งหมดลง min-priority queue ตาม frequency
  2. ดึง 2 ตัวที่ frequency ต่ำสุดมารวมเป็น node ใหม่ น้ำหนักผลรวม
  3. ใส่ node ใหม่กลับเข้า queue
  4. ทำจนเหลือ root เดียว แล้วกำหนด 0/1 ที่กิ่ง

Time โดยทั่วไป O(n log n) ด้วย min-heap

รหัส Huffman เป็น prefix-free: ไม่มี codeword ใดเป็น prefix ของอีก codeword จึงถอดรหัสได้โดยไม่กำกวม

17) Complexity Classes — P, NP, NP-Complete, NP-Hard
อ้างอิงสไลด์: Week 10 • P, NP, and NP-Complete (Polynomial Time, P, NP, NP-Complete, NP-Hard และ Polynomial Reduction)
Classความหมายโดยสรุป
Pปัญหาแบบ decision ที่แก้ได้ในเวลา polynomial ด้วย deterministic algorithm
NPเมื่อมี certificate/คำตอบที่เสนอมา สามารถตรวจสอบได้ในเวลา polynomial (เทียบเท่ากับ nondeterministic polynomial time)
NP-Completeอยู่ใน NP และเป็น NP-Hard; เป็นปัญหาที่ยากที่สุดกลุ่มหนึ่งใน NP ภายใต้ polynomial reduction
NP-Hardทุกปัญหาใน NP ลดรูปมาได้; ไม่จำเป็นต้องอยู่ใน NP หรือเป็นปัญหาแบบ decision

ความสัมพันธ์ที่รู้: P ⊆ NP. ยังไม่รู้ว่า P = NP หรือ P ≠ NP

ตัวอย่าง: SAT และ 3-SAT เป็น NP-Complete; TSP แบบ decision (“มี tour ระยะทางไม่เกิน K หรือไม่?”) เป็น NP-Complete ส่วน TSP แบบ optimization เป็น NP-Hard

Polynomial Reduction: A ≤ₚ B

แปลงอินสแตนซ์ของ A เป็นอินสแตนซ์ของ B ได้ในเวลา polynomial โดยรักษาคำตอบ yes/no: A แก้ได้ด้วยการแปลงไปแก้ B

ทิศทางสำคัญมาก: ถ้าจะพิสูจน์ว่า B เป็น NP-Hard ให้เริ่มจากปัญหาที่รู้แล้วว่ายาก A และแสดง A ≤ₚ B (ลดปัญหายากไปหา B) ไม่ใช่ B ≤ₚ A

ถ้า A ≤ₚ B และ B อยู่ใน P ⇒ A อยู่ใน P ด้วย

ไม่พบบทเรียนที่ตรงกับคำค้น ลองคำอื่น เช่น “DP”, “Prim” หรือ “NP”

Checklist ก่อนเข้าห้องสอบ

ข้อสอบห้ามอุปกรณ์อิเล็กทรอนิกส์ ดังนั้นให้ใช้เว็บนี้เพื่อฝึกก่อนสอบ แล้วซ้อมเขียนตารางลงกระดาษจากความจำ

จุดที่มักสับสน

  • Warshall vs Floyd: ไปถึงไหม vs ระยะทางสั้นสุดทุกคู่
  • Prim/Kruskal vs Dijkstra: MST vs shortest paths
  • 0/1 vs Fractional: แบ่งชิ้นไม่ได้ vs แบ่งได้
  • DP vs Greedy: เปรียบเทียบคำตอบย่อยหลายทาง vs เลือกเฉพาะหน้าตามกฎ
  • NP vs NP-Hard: NP ตรวจ certificate ได้เร็ว; NP-Hard ไม่จำเป็นต้องอยู่ใน NP
  • A ≤ₚ B: ลด A ไป B หมายความว่าแก้ B ได้เร็วแล้วช่วยแก้ A ได้เร็ว

เทคนิคจำสูตรให้ใช้เป็น

แทนที่จะจำสูตรลอย ๆ ให้จำความหมายของตัวแปรก่อน เช่น

  • dp[i][w]: ใช้ของ i ชิ้นแรก ภายใต้น้ำหนักไม่เกิน w ได้มูลค่าสูงสุด
  • D[i][j]: ระยะทางที่ดีที่สุดจาก i ไป j
  • T[i][j]: มีเส้นทางจาก i ไป j หรือไม่
  • dist[v]: ระยะทางที่ดีที่สุดที่รู้จาก source ถึง v ณ ตอนนี้

จากนั้นถามว่า “ถ้าอนุญาตให้ใช้ทางเลือก/จุดกลาง/สิ่งของเพิ่มขึ้น ค่าจะอัปเดตอย่างไร?” นั่นมักนำไปสู่ recurrence
